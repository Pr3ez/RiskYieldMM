# V4.9D Causal Ingress and Automatic Output Protocol Freeze

**Date:** 2026-07-17

**Status:** Implemented and accepted as a bounded local checkpoint

**Roadmap position:** Stage 1 critical corrections, after the bounded V4.9C
application-egress checkpoint and before V4.9E actor-ordered provider ACK,
terminal, and positive TLS/TCP shutdown integration

## 1. Decision

V4.9D connects the retained TLS/WebSocket driver to the V4.9C session actor for
one bounded causal ingress slice. One runtime call may acquire and durably adopt
exactly one RAW plaintext batch. This frame-at-a-time path then drains every
complete oldest WebSocket frame or structural-error prefix from the already
durable bytes, one parser transition at a time. An incomplete suffix remains
attributed to its exact RAW receipts and may be completed by a later runtime
call.

An RFC 6455 Ping or Close response generated by the pinned Sans-I/O protocol is
not a receive-side callback. It becomes an actor-ordered outbound operation and
uses the same exact-wire, atomic wire/permit, staged TLS, write-ahead kernel
attempt/result, and local-dispatch path as V4.9C application output. Pending
automatic output has priority over later application output.

The receive path may read ciphertext into the TLS incoming `MemoryBIO`, but it
must never flush post-handshake TLS output directly to the socket. If
`SSLObject.read()` requires a write or the outgoing `MemoryBIO` contains bytes
outside an already actor-authorized output, the bounded V4.9D path fails closed
before a socket write. A later protocol must represent such TLS-control output
in the actor vocabulary.

The public live factory remains closed. V4.9D does not establish provider
authority, live readiness, clean connection termination, completed-bar
authority, trading safety, predictive edge, or profitability.

## 2. Exact scope

### 2.1 Included

- the coalesced post-upgrade plaintext retained by V4.9B, or one continuing
  bounded TLS plaintext batch, as the sole RAW batch acquired by one runtime
  call;
- exact RAW bytes committed to the canonical projection and actor before any
  newly acquired byte reaches the WebSocket parser;
- store-minted RAW-receipt adoption under the private session-actor lock;
- a bounded durable plaintext FIFO with exact source slices across one or more
  RAW receipts;
- one independently delineated complete frame or structural-error prefix per
  parser mutation;
- parser cursor, frame, retained-tail, fragmentation, error, and generated
  automatic-output evidence in actor order;
- projection verification against the canonical stored RAW bytes, not only
  caller-supplied lengths or hashes;
- automatic Pong and Close output through the V4.9C outbound FIFO and send
  evidence path;
- fail-stop behavior after uncertain storage, parser, TLS, or kernel effects;
  and
- bounded local and loopback falsification of these rules.

### 2.2 Explicitly deferred to V4.9E

- provider application-message classification and exact subscription-ACK
  binding in the actor order;
- actor-ordered subscription completion, ACK deadline, timeout, and all
  terminal transitions;
- the positive WebSocket Close, TLS `close_notify`, TCP write-half-close, peer
  alert, and TCP EOF sequence;
- positive actor-authorized TLS 1.3 post-handshake control traffic;
- recovery of a live parser/TLS object across process restart;
- a production queue-depth and overload policy; and
- any public live-factory admission.

V4.9D may detect Close, TLS EOF, truncation, timeout, or an output requirement,
but detection alone is not the complete positive terminal protocol. Until
V4.9E, such paths are fail-stop/non-promotion boundaries rather than evidence
of a cleanly completed connection.

## 3. Frozen information flow

The only admitted positive ingress flow is:

```text
runtime owns exact session actor + Linux socket owner + governed clock
→ serialize one ingress operation under the runtime/owner boundary
→ choose retained coalesced post-upgrade plaintext, otherwise read one batch
→ construct exact RawIngressCommitV4 from driver-owned plaintext chunks
→ atomically persist canonical RAW receipt + RAW actor edge
→ actor verifies and consumes the store-minted one-shot handoff
→ exact driver adopts those same bytes into its durable ingress FIFO
→ combine them with any older attributed incomplete tail
→ delineate the exact oldest complete frame/error prefix
→ feed only that prefix to pinned websockets Sans-I/O
→ persist one exact parser transition against canonical RAW source slices
→ if automatic output exists, dispatch it completely through the actor FIFO
→ repeat only for complete units already present in this adopted RAW extent
→ return progress; do not acquire a second RAW batch in the same runtime call
```

A normal need-more-data outcome is not a parser transition. It retains the
exact incomplete tail and returns after the current one-RAW-batch call. The
next call may append another durable RAW receipt and delineate a frame whose
source slices span both receipts.

The runtime API does not accept a caller-selected socket, parser, plaintext,
RAW record, frame, protocol-output callback, wire, permit, TLS artifact, or
sender. Those are retained capabilities of the admitted runtime.

## 4. Information-availability and durability invariants

### 4.1 RAW before parse

For every byte consumed by Sans-I/O, a canonical RAW receipt must already exist
and the exact RAW actor event must already be adopted. Content-equivalent
reconstruction is not authority. If RAW persistence or the actor handoff is
uncertain, no parser call is permitted and the session is fault-latched.

### 4.2 Exact byte attribution

Every parser transition names ordered source slices with:

- the canonical RAW receipt/event identity;
- the source chunk and absolute stream interval;
- the exact consumed intersection with the current frame/error unit; and
- the prior and resulting parser cursor.

Projection admission and full replay reconstruct those bytes from canonical
RAW records. Matching offsets, lengths, or a supplied SHA-256 value without
matching stored bytes is insufficient. There may be no gap, overlap, source
reordering, duplicated slice, or unattributed consumed byte.

### 4.3 Frame-at-a-time mutation

One parser mutation consumes exactly one oldest complete WebSocket frame or the
minimum prefix that establishes a structural protocol error. A whole RAW batch
is never fed as one opaque parser mutation because it may contain multiple
frames and therefore multiple actor obligations. The boundary detector proves
only that a parser unit is complete. The pinned `websockets` state machine
remains authoritative for fragmentation, Close payloads, protocol errors, and
generated output. Because direct Sans-I/O access exposes raw frame payloads,
the retained driver applies strict incremental UTF-8 validation across Text and
Continuation frames before application acceptance. An invalid sequence invokes
the pinned protocol failure path with Close code 1007.

One unit may emit at most one frame event and at most one automatic masked
client Pong or Close frame. Any other event/output cardinality is outside the
V4.9D vocabulary and fails closed.

### 4.4 Cross-RAW continuity

An incomplete valid header or payload never advances Sans-I/O state. Its bytes
remain in the bounded durable FIFO with exact RAW-source attribution. When a
later RAW batch completes the unit, the single resulting parser transition
commits every contributing source slice in stream order. This is byte-stream
continuity, not a claim that one RAW receipt equals one WebSocket frame or
message.

Fragmented WebSocket messages are likewise a sequence of individually durable
frame transitions. Parser fragmentation state advances in actor order; it is
not reconstructed from a later message endpoint.

### 4.5 One RAW batch per runtime call

One call may drain several already complete parser units from its one adopted
RAW batch, but it must not perform another socket read in that call. This keeps
the effect boundary bounded, makes cancellation/storage outcomes classifiable,
and prevents an unbounded hot stream from monopolizing the actor. A later
queue/fairness policy may refine scheduling without weakening this durability
rule.

## 5. RFC control semantics and automatic output

[RFC 6455](https://www.rfc-editor.org/rfc/rfc6455.html) requires control frames
to be final and no larger than 125 payload bytes. In an open WebSocket state, a
received Ping requires a Pong unless a Close was already received; the Pong
must carry identical application data. A received Close participates in the
closing handshake and forbids later application data.

V4.9D therefore requires:

1. a durable parser event before its automatic output can be authorized;
2. an open-state Ping parser event to carry exactly one generated Pong wire;
3. that Pong's decoded payload to equal the triggering Ping payload byte for
   byte;
4. a generated Close, when applicable, to remain linked to its parser cause;
5. automatic operations to consume the oldest unconsumed parser obligation;
6. exact automatic wire plus its deterministic one-shot permit to commit in
   one actor transaction before TLS state advances;
7. exact TLS ciphertext to become durable before any kernel attempt; and
8. complete local submission or a terminal uncertain-send state before a later
   parser/application output may overtake it.

Bybit's JSON `{"op":"ping"}` heartbeat is an application Text message, not
an RFC control Ping. It remains a separately authorized application operation
and cannot satisfy or replace the automatic Pong rule.

## 6. No hidden TLS writes

Python's `SSLObject` and `MemoryBIO` separate TLS state progression from
network I/O, but a read can encounter protocol work that requires outgoing
bytes. The earlier compatibility reader could drain those bytes directly.
That behavior is forbidden in the causal V4.9D ingress path because no actor
wire, permit, TLS artifact, or write-ahead kernel attempt would precede the
socket effect.

The V4.9D reader admits only:

```text
nonblocking socket recv
→ incoming MemoryBIO write
→ SSLObject plaintext read
→ exact pending RAW batch returned to the runtime
```

Before and after every read step, unexpected outgoing BIO bytes, staged output,
or `SSLWantWriteError` cause a typed fail-closed outcome before any socket
write. This is deliberately conservative. It does not claim full TLS 1.3
post-handshake interoperability; V4.9E must add an actor-ordered representation
before that traffic can be sent.

## 7. Failure and crash-prefix rules

| Last proven boundary | Required interpretation |
|---|---|
| plaintext retained by driver, no RAW commit | not parser-authorized; abort/fault, no parse |
| RAW canonical commit uncertain | storage-uncertain terminal fence; no parse |
| RAW actor event durable, driver adoption not complete | evidence only; do not reconstruct a live parser capability after restart |
| parser mutated, parser-event persistence fails or is uncertain | parser state is unreplayable; abort/fault; no automatic socket write |
| parser event durable, automatic wire/permit batch rolls back | no TLS advance and no send authority |
| automatic wire/permit durable, TLS artifact absent | no send proven; one-shot authority is not silently recreated |
| TLS artifact durable, kernel attempt absent | no send proven; no inferred retry authority |
| kernel attempt without conclusive result | unknown delivery; terminal fence |
| positive partial result without full dispatch | exact accepted prefix known, remainder unknown; terminal fence on recovery |
| local dispatch complete | local kernel acceptance only; not peer processing or provider ACK |

Cancellation does not weaken these interpretations. Once a non-replayable
parser, TLS, or kernel effect may have occurred, cleanup must be shielded long
enough to persist the strongest available terminal evidence; failure to do so
remains a fault-latched uncertainty, never permission to retry.

## 8. Rejected alternatives

### Parse the entire RAW batch in one Sans-I/O call

Rejected. One call may emit several frames and several automatic outputs while
the actor schema requires independently attributable, FIFO-ordered
obligations. It also obscures the precise mutation that introduced a parser
failure.

### Parse first, then persist RAW and parser facts together

Rejected. Storage failure would leave mutated protocol state with no durable
proof of the bytes that caused it, and a restart could not distinguish unseen
input from already consumed input.

### Write `data_to_send()` directly from the receive loop

Rejected. It bypasses exact-wire persistence, the one-shot permit, TLS artifact
ordering, the write-ahead kernel attempt, and the session actor's FIFO.

### Store a list of automatic outputs on one batch parser event

Rejected for this bounded checkpoint. It makes partial dispatch and ordering
ambiguous. Exact one-frame parser transitions make each obligation independently
causal and auditable.

### Trust parser metadata without replaying canonical RAW bytes

Rejected. A forged equal-length source range or equal-shape metadata could
attribute a real frame to unrelated plaintext. Canonical RAW reconstruction is
required at append and full verification.

### Let application output run while a Pong or Close is pending

Rejected. It violates the actor's total order and may delay protocol-mandated
output behind optional work. After Close, application data is forbidden.

### Flush post-handshake TLS output opportunistically

Rejected. A hidden network write cannot be reconciled with the V4.9C durable
send protocol. Unsupported TLS-control output fails closed until represented
explicitly.

## 10. Primary-source basis

- [RFC 6455](https://www.rfc-editor.org/rfc/rfc6455.html) defines frame
  boundaries, control-frame limits, Ping/Pong semantics, fragmentation, and the
  WebSocket closing handshake. It does not define local durable evidence or
  crash recovery.
- [`websockets` 16 Sans-I/O integration](https://websockets.readthedocs.io/en/16.0/howto/sansio.html)
  requires integrations to feed received data, retrieve events, and promptly
  drain protocol-generated output such as Pong and Close. It supplies protocol
  mechanics, not this repository's authority model.
- [`websockets` 16 Sans-I/O client API](https://websockets.readthedocs.io/en/stable/reference/sansio/client.html)
  documents the client protocol's `receive_data()`, `events_received()`, and
  `data_to_send()` boundaries.
- Python's [`ssl` Memory BIO documentation](https://docs.python.org/3.12/library/ssl.html#memory-bio-support)
  documents nonblocking `SSLObject`/`MemoryBIO` operation and the need to handle
  `SSLWantReadError` and `SSLWantWriteError`. It does not authorize direct
  socket effects outside the actor.

These sources support the transport mechanics. The RAW-first durable order,
canonical receipt authority, cross-RAW source slicing, actor transactions, and
fail-stop crash interpretation are repository engineering decisions that must
be justified by tests and operational evidence.

## 11. Acceptance boundary and next gate

V4.9D is accepted as the latest bounded local checkpoint. The runtime now
durably adopts one RAW plaintext batch before parsing, retains exact cross-RAW
frame attribution, advances one parser unit at a time, validates fragmented
text incrementally, and routes automatic Pong or Close output through the
V4.9C actor send path. Hidden TLS writes fail closed. The public live factory
remains closed.

V4.9E is the next causal transport slice. It must place provider application
messages, the exact subscription ACK and completion state, deadlines and
terminal facts, WebSocket Close completion, local and peer TLS `close_notify`,
TCP half-close/EOF, and any positive TLS post-handshake output into one
replayable actor order. Only after that local protocol is falsified should the
project proceed to privileged deployment, provider/certificate conformance,
process-crash campaigns, and long no-trading soaks.
