## 1. Decision

V4.9F-A2 is not one implementation step. It is split into three separately
reviewed and falsifiable gates:

```text
accepted V4.9F-A1 local admission
    -> V4.9F-A2-M measurement-only implementation
    -> immutable measurement artifacts from frozen workloads
    -> numeric threshold analysis and independent review
    -> signed threshold-policy freeze
    -> V4.9F-A2-E enforcement implementation
    -> adversarial enforcement and replay acceptance
```

The split is mandatory:

- **A2-M** may observe the system but must not change transport, parser, actor,
  journal, terminal, retry, or scheduling outcomes.
- The **threshold freeze** may derive values only from complete, immutable A2-M
  artifacts and must bind them to an exact deployment/software/workload class.
- **A2-E** may pause reads, schedule cooperative parser continuations, append
  actor-owned capacity transitions, and converge terminal overload only under
  the newly signed policy.

No percentage, latency, byte watermark, parser quantum, SQLite timeout, or
terminal grace interval in this document is a production value. Primary
sources establish mechanisms and hazards, not RiskYieldMM's numeric limits.

The preferred A2-E architecture is an actor-owned cooperative capacity
protocol, not a background parser worker:

```text
observe every governed layer
-> enter pressure when any layer crosses high
-> stop new reads when downstream cannot safely accept more
-> drain the already-durable causal prefix in bounded work turns
-> resume only when every required layer reaches low
-> converge one actor-ordered terminal outcome on hard capacity/freshness breach
```

## 3. A1 generic capacity rejection is unreachable

This is a corrective finding relative to the descriptive wording of the A1
freeze. It does not invalidate A1's singleton bound, FIFO, cancellation, or
shutdown-barrier evidence.

Let the exact A1 command-kind set be:

```text
K = {INGRESS, SUBSCRIPTION_DISPATCH, ACK_DEADLINE_EXPIRY, LOCAL_SHUTDOWN}
```

The policy constructor requires:

```text
maximum_active_and_waiting_commands = |K| = 4
maximum_reserved_work_units = sum(reservation(kind) for kind in K)
reservation(kind) > 0 for every kind
```

The gate rejects a new request if its kind is already active or waiting before
it evaluates count/work capacity. Therefore every request which reaches the
generic capacity check has a kind not already in the outstanding set. For any
proper subset `S` of `K` and any `k` in `K - S`:

```text
|S| < 4
sum(reservation(s) for s in S) + reservation(k)
    <= sum(reservation(kind) for kind in K)
```

Consequently neither count nor work can exceed the signed limit. Once all four
kinds are outstanding, every possible fifth request duplicates a kind and is
rejected by the earlier duplicate branch. Under the exact valid policy:

```text
capacity_rejections == 0
```

is an invariant, not evidence that tested load remained below a meaningful
capacity.

A2-M must add an exhaustive state-space oracle over all command-kind subsets
to preserve this conclusion. A2 documentation and dashboards must distinguish:

- singleton/duplicate admission rejection;
- terminal-barrier rejection;
- queue-start expiry; and
- measured downstream pressure or hard capacity breach.

A2 must not silently reinterpret A1's abstract work weights as CPU, bytes,
parser frames, database operations, memory, or freshness.

| [SQLite `page_count`](https://www.sqlite.org/pragma.html#pragma_page_count) and [`freelist_count`](https://www.sqlite.org/pragma.html#pragma_freelist_count) | The connection PRAGMAs return total database-file pages and unused pages | They cannot be inferred from file length, especially with WAL; an observer connection can add locking and timing effects | The current filesystem-only adapter leaves both fields unavailable with `SQLITE_CONNECTION_PRAGMAS_NOT_SAMPLED`; add them only through a separately designed and neutrality-tested connection protocol |
| [SQLite limits](https://www.sqlite.org/limits.html) | Runtime and database size limits can convert growth into explicit failure such as `SQLITE_FULL` | No RiskYieldMM limit values | Include limit/fill fault campaigns before enforcement acceptance |
| [SQLite interrupt](https://www.sqlite.org/c3ref/interrupt.html) | `sqlite3_interrupt()` aborts operations at the earliest opportunity and may roll back an explicit write transaction | It may arrive after completion; asyncio cancellation does not invoke it automatically | Do not claim timeout preemption without an explicit, tested storage protocol |
| [Python asyncio concurrency](https://docs.python.org/3.12/library/asyncio-dev.html#concurrency-and-multithreading) | While one task executes, no other task executes on that event-loop thread; blocking I/O and CPU work delay all tasks | No automatic protection from synchronous SQLite or chain rebuilding | Measure loop lag and synchronous critical-section duration |
| [Python `asyncio.Lock`](https://docs.python.org/3.12/library/asyncio-sync.html#asyncio.Lock) | The task mutex is not thread-safe; `acquire()` waits until the lock is unlocked and waiting acquisition is fair | The documentation does not state a reentrancy or owner-tracking guarantee, and a lock does not freeze kernel or peer state | The current public flow observer is called only at a quiescent boundary because its concrete path acquires runtime orchestration, owner I/O, and driver actor locks; do not call it from a path that already owns one of those locks |
| [Python `asyncio.sleep`](https://docs.python.org/3.12/library/asyncio-task.html#asyncio.sleep) | `sleep(0)` always suspends the current task and lets other tasks run | It cannot let later transport commands enter while the orchestration lock/grant remains held | A parser quantum needs an explicit continuation protocol, not only `sleep(0)` |
| [Python task cancellation](https://docs.python.org/3.12/library/asyncio-task.html#task-cancellation) | `CancelledError` is raised at the next opportunity, directly subclasses `BaseException`, and should generally be propagated after `try/finally` cleanup | It does not preempt synchronous parser, SQLite, reducer, or callback work and does not by itself produce a completed measurement artifact | The schema reserves `CANCELLED`; the current runner cancels its pending lag probe and propagates cancellation without a post-snapshot, so a persisted cancelled-run terminal record remains explicit hardening work |
| [Python `asyncio.wait_for`](https://docs.python.org/3.12/library/asyncio-task.html#asyncio.wait_for) | Cancellation is cooperative and total wait may exceed the nominal timeout while cancellation finishes | It cannot interrupt synchronous parser, SQLite, or reducer work | Elapsed time is a watchdog/measurement, not the only service bound |
| [Python `call_soon`](https://docs.python.org/3.12/library/asyncio-eventloop.html#asyncio.loop.call_soon), [event-loop clock](https://docs.python.org/3.12/library/asyncio-eventloop.html#asyncio.loop.time), and [`time.monotonic`](https://docs.python.org/3.12/library/time.html#time.monotonic) | `call_soon()` schedules one callback for the next loop iteration in registration order; `loop.time()` returns float seconds from the loop's internal monotonic clock; integer monotonic APIs avoid float precision loss where they are available | One callback delay is not a maximum-lag series; multiplying a float by one billion does not guarantee nanosecond resolution or identity with `time.monotonic_ns()` | Name the current observation one scheduled callback delay overlapping the operation, retain loop implementation/resolution, compare only within the loop-clock domain, and keep debug slow-callback logging as corroboration |
| [Linux `clock_gettime(3)`](https://man7.org/linux/man-pages/man3/clock_gettime.3.html) | `CLOCK_MONOTONIC` excludes suspend while `CLOCK_BOOTTIME` includes it | The domains cannot be safely mixed by assuming one fixed offset | Record local loop lag and governed physical age separately |
| [Linux procfs process memory](https://docs.kernel.org/filesystems/proc.html) | `/proc/PID/statm` reports resident pages but RSS accounting may be asynchronous and imprecise; `smaps_rollup` accumulates mapping statistics; PSS divides shared pages proportionally | RSS and PSS are not interchangeable, simultaneous, or exact process-owned-byte measurements; PSS can change with other processes and the scan has non-trivial observer cost | Record the method and span separately; use RSS as approximate and PSS as proportional attribution, never as an enforcement threshold before neutrality and overhead tests |
| [Linux cgroup v2 `memory.current`](https://docs.kernel.org/admin-guide/cgroup-v2.html#memory-interface-files) | `memory.current` reports bytes used by a cgroup and its descendants and includes tracked user, cache, kernel, and TCP-buffer memory | It is not target-process RSS or PSS; a unified hierarchy mounted at the assumed path is deployment-specific | Label it cgroup-wide, bind cgroup/mount identity, and record it unavailable on unsupported or differently mounted deployments |
| [Linux NAPI](https://docs.kernel.org/networking/napi.html#datapath-api) and [`netdev_budget_usecs`](https://docs.kernel.org/admin-guide/sysctl/net.html#netdev-budget-usecs) | Kernel packet polling uses a count budget and can also stop on elapsed time | Kernel values and semantics do not select user-space quanta | Evaluate frame-count plus byte/work quanta; use elapsed time as an observed guard |
| [Linux `fs-verity`](https://docs.kernel.org/filesystems/fsverity.html) | A read-only file may be measured once and subsequently read through kernel Merkle-tree verification; the file digest can be retrieved without re-reading the full file | It does not attest mutable files, the running process, Python objects, or deployment policy, and it requires a supported filesystem and controlled enablement | Evaluate it as a deployment-qualified challenger to repeated whole-file hashing; do not weaken the existing closure until provisioning and tamper tests pass |
| [Linux `dm-verity`](https://docs.kernel.org/admin-guide/device-mapper/verity.html) | A read-only block device can verify blocks on demand against a trusted root hash | It does not identify individual runtime artifacts or make a mutable development tree admissible | Consider it only for a separately built immutable deployment image, not as an A2 parser optimization |

## 5. Alternatives and selected candidates

| Candidate | Disposition | Reason |
|---|---|---|
| One fixed byte watermark for the whole runtime | Rejected | It hides which layer is saturated and cannot represent actor time, SQLite locks, control-output age, or kernel in-flight bytes |
| High watermark without a lower resume threshold | Rejected | It flaps when occupancy oscillates near one boundary |
| Read pause as the terminal overload response | Rejected | It can move pressure into TLS and kernel queues and increase data age |
| Immediate terminal on first high crossing | Rejected | It converts ordinary transient bursts into session loss without measuring recovery |
| Time-only parser quantum | Rejected | Python cannot preempt a synchronous unit at the deadline; observed time can overshoot without a byte/count bound |
| Frame-count-only quantum | Measurement candidate, not sufficient alone | Tiny and maximum-sized frames impose radically different byte and actor costs |
| Byte-only quantum | Measurement candidate, not sufficient alone | Many tiny control/data frames can create high actor/journal work at low byte count |
| Hybrid frame plus byte/work quantum | Preferred A2-E candidate | It bounds admitted discrete work and byte volume; elapsed time remains a watchdog between indivisible units |
| Background parser queue/worker | Rejected for A2 | It moves effect ownership, complicates cancellation/final-writer semantics, and creates another causal queue |
| `asyncio.to_thread()` around current journal calls | Rejected as a local patch | The journal is intentionally thread/loop-bound; moving calls requires a new authority-owning serialized writer protocol |
| Fail-fast or short bounded SQLite busy policy | Preferred synchronous baseline for threshold evaluation | It bounds loop blockage but may convert contention into storage failure; the exact limit must be measured and signed |
| Dedicated journal thread/process | Architectural challenger | It can isolate loop latency only if it owns its SQLite connection and preserves exact FIFO capability and completion semantics |
| WAL | Storage challenger | It may improve some workloads but retains one writer and adds checkpoint/reader-starvation behavior |
| Actor-internal pressure transitions | Preferred | It preserves the existing final writer and durable event chain |
| Generic runtime `fence_backpressure` bypass | Rejected | It conflicts with the V4.9E actor-owned terminal boundary |

## 6. A2-M measurement-only contract

### 6.1 Behavioral neutrality

A2-M instrumentation must be removable and must not alter:

- socket read size, timing decision, or retry behavior;
- TLS read/write ordering or BIO mutation;
- WebSocket parser calls, event order, or generated output;
- RAW receipt, actor-event, projection-receipt, parser-event, or terminal bytes;
- A1 ticket order, rejection class, queue deadline, or shutdown barrier;
- SQLite journal mode, busy timeout, transaction boundaries, or synchronous
  ownership; or
- public live-factory denial.

For deterministic workloads, instrumentation-off and instrumentation-on runs
must produce identical canonical durable actor/projection prefixes and physical
outcome classifications. Only separately stored A2-M measurement artifacts and
their own timestamps may differ.

### 6.2 Required observation layers

Every schema-admitted sample field uses explicit units and a named observation
method. Missing or unsupported values for those fields are recorded as
`UNAVAILABLE`, never as zero. Target-surface observations not admitted by the
current Raw V6 schema are absent, not silently represented as available fields.

| Layer | Required A2-M observations |
|---|---|
| A1 admission | active/waiting count, kinds, oldest age, abstract reservations, actual entry wait, rejection class, original admission epoch/sequence |
| Kernel receive | `SIOCINQ` unread-byte point observation, literal Linux-doubled `getsockopt(SO_RCVBUF)` value, read readiness, snapshot errno, sample span; never inferred headroom |
| Kernel send | `SIOCOUTQ` unsent-byte point observation, literal Linux-doubled `getsockopt(SO_SNDBUF)` value, write readiness, accepted-octet progress, sample span; never peer receipt |
| TLS input/output | incoming/outgoing `MemoryBIO.pending`, TLS plaintext pending, ciphertext read/written per operation, WANT_READ/WANT_WRITE counts |
| Durable ingress | pending RAW octets/chunks, durable-buffer octets, complete-unit availability, retained incomplete tail, oldest RAW age, RAW ingress sequence and receipt |
| Parser work | frames/units, source octets, payload octets, fragments, parser errors, application completions, automatic-output chunks/octets, per-unit elapsed and CPU observations |
| Actor | retained event count, append/batch duration, validation duration where separable, rebuild duration where separable, event-kind counts, pending wire/control obligations |
| SQLite/projection | transaction start/commit/rollback duration, BUSY/FULL/IOERR/INTERRUPT classification, busy-timeout configuration, sequential database/journal/WAL/SHM filesystem occupancy, connection-derived page/freelist counts when neutrally available, transaction rows/bytes |
| Event loop | expected versus actual scheduled-probe time; the current runner records one `call_soon()` callback delay overlapping the operation, while a repeated/maximum-lag series, slow-callback corroboration, and a persisted cancellation terminal remain future hardening |
| Process/host | approximate procfs RSS, proportional PSS, separately labeled cgroup-and-descendant `memory.current`, high-water RSS, CPU time, GC counts/pauses where available, kernel/Python/OpenSSL/SQLite/websockets versions, filesystem, mount, and cgroup identity |
| Freshness/control | oldest unparsed durable byte age, pressure-episode age, Ping parsed-to-Pong terminal latency, Close parsed-to-response terminal latency, ACK/shutdown command wait |

Kernel queue values are snapshots, not atomic cross-layer states. Samples must
carry a begin/end timestamp or a declared point sample and may not be combined
as if all layers were observed simultaneously.

The table is the A2-M target surface, not a claim that the present Raw V6
runner (with the V2 ingress-workload schema) fills every field. For fields
admitted by the current Raw V6 schema, the runner supplies boundary
observations or explicit nulls with reason codes. Several target-surface fields
remain absent from the schema rather than present as nulls, including kernel
readiness/errno, TLS per-operation/WANT counts, durable-tail/age, parser
work/timing, actor duration/event-kind/rebuild attribution, SQLite transaction
spans and rows, full A1 kind/age history, repeated loop-lag series, process
CPU/GC data, and freshness/control latency. In particular the runner does not
synthesize an in-operation peak, derive SQLite page/freelist counts from file
size, turn one event-loop callback delay into a maximum-lag statistic, or turn
propagated task cancellation into a completed measurement record. Missing
admitted fields remain visible rather than being converted to zeros or
enforcement decisions; absent target fields remain explicit implementation
work.

### 6.3 Clock domains

Record at least three separate notions:

```text
loop_time_ns          local asyncio scheduling and queue latency
boottime_ns           governed physical/freshness duration including suspend
wall_time             forensic correlation only
```

Do not calculate governed BOOTTIME deadlines by subtracting local event-loop
time. The current scheduled probe computes one delay from its initial
`loop.time()` and the callback's later `loop.time()`; it persists the delay,
not both endpoints or a repeated series. Suspend experiments compare that
local lag with separately sampled BOOTTIME evidence.

`loop_time_ns` is the serialization unit for the current float-derived
`loop.time()` observation; the suffix does not promise nanosecond clock
resolution. The current manifest binds the loop implementation and the
observer-monotonic resolution, but it has no dedicated event-loop-clock
resolution field; adding one remains manifest hardening. Values are comparable
only within that loop-clock domain and must not be treated as
`time.monotonic_ns()` or subtracted from BOOTTIME.

### 6.4 Immutable artifact contract

#### 6.4.1 Selected exact-evidence V5 profile

The next Step 2 persistence gate uses a new mandatory raw-evidence schema. It
does not reinterpret the exploratory V4 bytes and it does not make missing V4
observations reconstructable. Native V4 campaigns must be rerun under V5;
automatic upgrade or hydration is forbidden.

V5 retains the exact four-member closure because the current sampler and
replay boundary are sample-oriented and the durable streaming publisher is a
later Step 2 gate. Each sample now owns all evidence needed to reconstruct its
successful returned ingress result:

- one canonical base64 string containing the concatenated serialized
  WebSocket output bytes;
- the ordered non-zero chunk-octet lengths needed to recover every physical
  chunk boundary;
- the ordered logical Close/Pong opcode and payload bytes;
- all returned RAW, parser, dispatch, actor-tail, retained-parser, and full A1
  grant fields; and
- role-bound initial, before-operation, and after-operation runtime boundaries,
  including the complete quiescent A1 snapshot rather than selected counters.

The evaluated storage alternatives were:

| Candidate | Decision | Reason |
|---|---|---|
| Canonical base64 payload per physical chunk | Rejected | Exact, but repeats JSON keys/string framing for every chunk and scales poorly for fragmented output |
| One canonical base64 stream plus ordered chunk lengths inside the sample | **Selected for V5** | Exact bytes, exact chunk partition, direct sample-identity commitment, existing canonical JSON/replay machinery, and no new partially implemented artifact parser |
| Mandatory fifth binary-pack member | Deferred to a future streaming profile | More compact and compatible with an OCI-like opaque-payload descriptor, but requires a new bounded binary grammar, separate record/sample linkage, publisher ordering, and another closure; the current sampler still retains all runs in memory, so adding it now does not solve campaign-scale streaming |
| External content-addressed object | Rejected as authoritative evidence | A digest can validate a retrieved candidate but the bundle becomes incomplete when the object is absent |
| Digest/count/grouping only | Rejected for V5; legacy V4 only | Cannot reconstruct bytes or independently falsify the physical/logical mapping |

Base64 is an encoding, not proof. V5 requires canonical re-encoding, reconstructs
the exact ordered chunks before acceptance, and recomputes concatenated-output,
ordered-batch, count, octet, and frame-grouping commitments. The sample identity
therefore commits the exact bytes and their partition directly; bundle integrity
still commits the exact canonical sample stream. A digest-only record, an
external content-addressed object, or an optional fifth member is not an
authoritative V5 sample.

The source-derived maximum serialized automatic output for one ingress sample
is 4,292,608 octets: at most 32,768 automatic control frames and at most 131
wire octets per masked Close/Pong frame. This is an artifact-decoder safety
bound, not a measured capacity threshold. Decoders reject oversized encoded
values before base64 allocation and reject any decoded, partitioned, or
reconstructed value outside the same bound. A future binary-pack/streaming
profile would require another explicit schema and artifact-closure review; it
must not silently change V5.

Returned-progress availability is explicit. A returned result with zero output
is exact evidence and carries an empty byte stream and empty chunk partition.
An exception which returns no progress carries
`RETURNED_PROGRESS_UNAVAILABLE_AFTER_EXCEPTION` and cannot populate zero-output
commitments as though they had been observed. V5 persists the after boundary
and adverse classification even when actor state advanced. Recovering exact
completed-prefix bytes after an exception remains the separate failed-prefix
gate.

Boundary and progress disagreement is evidence, not a reason to omit the
record. Identity, type, bounds, admission decomposition, and monotonic
structural invariants are always checked. Returned grant wait and reservation
must not exceed the after-boundary historical maxima even for adverse evidence.
Exact last-started wait equality and the remaining returned actor/grant
alignment with before/after boundaries are required only for a claimed clean
measurement `PASS`, so foreign-activity evidence remains serializable as
`ERROR`. The raw V5
correctness record remains provisional and non-passing until the separately
versioned evidence-derived finalizer exists.

The storage choice follows [RFC 8493](https://www.rfc-editor.org/rfc/rfc8493.html)
on complete packages and verified payload bytes, the
[OCI descriptor](https://specs.opencontainers.org/image-spec/descriptor/) model
for digest-and-size binding of opaque content, and
[RFC 6455 framing](https://www.rfc-editor.org/rfc/rfc6455.html#section-5.2) plus
[control-frame bounds](https://www.rfc-editor.org/rfc/rfc6455.html#section-5.5).
The future finalization separation follows the
[in-toto Statement v1](https://github.com/in-toto/attestation/blob/main/spec/v1/statement.md)
subject/predicate model and
[SLSA VSA](https://slsa.dev/spec/v1.2/verification_summary) verifier/policy/input
binding. None of those specifications authenticates a locally self-hashed
bundle; the future finalizer and external trust anchor remain mandatory.

The implemented V5 serialization profile is an **exploratory raw-evidence
foundation only**. It builds one content-addressed, uncompressed four-member
byte closure in memory so member-level replay remains exact:

```text
v4_9f_a2_measurement/<evidence_bundle_id>/
    manifest.json
    samples.jsonl
    correctness.json
    integrity.json
```

The directory above is the required publication layout, not an implemented
atomic or durable filesystem publisher. `artifact_bytes()` returns the four
members; immutable campaign publication remains implementation-sequence Step 4.
Here “raw evidence” means unsummarized sample records, including exact returned
physical WebSocket output chunks and runtime boundaries. It does not mean that
failed-operation prefixes which the runtime never returned have been recovered.

Every identity-bearing record carries the exact canonicalization and
measurement-schema versions plus its frozen record domain. Environment,
design, manifest, sample, correctness, and integrity identities hash the
explicit `{canonicalization_version, domain, payload, schema_version}`
envelope. `samples.jsonl` ends every record with one newline. `integrity.json`
commits the exact media type, byte count, record count, and ordinary SHA-256 of
every other member; it deliberately does not hash itself. The sample-stream
root is likewise an ordinary digest of exact JSONL bytes. `evidence_bundle_id`
is exactly the domain-separated integrity-record identity. Replay verifies the
canonical integrity record and raw-byte closure before decoding the three
committed manifest/sample/correctness records. Compression is not admitted by
this profile and would require a new profile.

`campaign_manifest_id` and `evidence_bundle_id` have deliberately different
meanings. The former identifies the frozen exploratory plan and exact physical
session. Two executions with the same manifest but different sample bytes keep
the same campaign-manifest identity and receive different evidence-bundle
identities. A directory named only by `campaign_manifest_id` is therefore not
an immutable evidence root.

`manifest.json` canonically commits the following declarations:

- declared code revision, source identity, and clean/dirty-tree status;
- A1 policy ID, declared runtime identity/version, and workload-corpus identity;
- the exact transport-session ID, driver-evidence nonce, and kernel-socket
  identity;
- `EXPLORATORY` as the only admitted phase;
- separate arbitrary-length canonical unsigned-text observer-monotonic,
  `CLOCK_BOOTTIME`, and event-loop clock origins, avoiding I-JSON precision
  loss after long host uptimes and forbidding cross-domain subtraction;
- the exact canonical JSON for every workload vector, its literal SHA-256,
  and a corpus root derived from the ordered workload records;
- declared kernel, CPU/affinity, Python/event-loop, OpenSSL, websockets, SQLite,
  filesystem, storage, and SQLite-pragma values and identities; and
- observer clock/resolution, warm-up/repetition counts, seeded trial order,
  exclusion/analysis identities, and the instrumentation-overhead method.

Canonical commitment proves that the bytes cannot later change without a new
manifest identity; it does not prove that every declared value was collected
from the running process. The current runner checks the manifest against the
runtime-owned session ID, driver nonce, kernel-socket identity, A1 policy, and
projection-storage device/inode. It has no production manifest collector for
the declared source revision/tree state, full runtime identity, or remaining
host/environment fields. Those values are therefore self-attested committed
declarations in the current exploratory profile.

A dirty tree is structurally admissible because the profile is exploratory and
commits its declared source-tree identity. `CALIBRATION` and `CONFIRMATION` payloads are
rejected, rather than being given authority before the real sampler, observer
neutrality, host qualification, and independent campaign protocol exist.

Each `samples.jsonl` record binds one operation span: campaign/workload/trial
identity; optional parent sample; distinct observer and underlying-operation
start/end offsets; separate observer-monotonic, BOOTTIME, and loop-time spans;
warm-up status; before/in-operation/after layer snapshots; input and output
chunk/octet counts; optional paired RAW-ingress commit, sequence, and ordered
batch hash; exact parser-event IDs; automatic-output source-parser IDs,
dispatch-completion IDs, exact physical bytes/chunk grouping, decoded logical
frames, complete returned A1 grant/timing, and role-bound runtime boundaries;
exact returned-grant or explicitly unavailable A1 admission attribution; exact
input and physical-output hashes;
separate logical observed/expected Pong-or-Close frame counts and hashes;
an exception class for a caught operation exception; and separate operation
versus measurement outcomes. Operation outcomes admit `PASS`, `FAIL`, `ERROR`,
and `CANCELLED`; a successful durable operation remains successful when a
later observer fails, while the measurement is independently `ERROR`. Parser,
actor, SQLite, admission, process, and event-loop state is represented only by
typed snapshots at this stage. All numeric offsets remain inside the exact
I-JSON integer range and are compared only within their declared clock domain.
The record stores and reconstructs the serialized output chunks and exact
initial/before/after runtime boundaries. A returned zero-output result is
distinct from unavailable progress after an exception.

`CANCELLED` is currently a schema value, not a claim that the ingress runner
persists a cancelled sample. The runner cancels its pending callback-delay
probe and propagates `CancelledError` without retry, shielding, or awaiting a
post-snapshot in the cancelled task. If cancellation reaches the ordinary
active-ingress non-terminal cleanup path after entry, the runtime aborts the
owner and enters `FAULT_LATCHED` before propagating; if actor terminal
convergence already exists, that stronger terminal state remains authoritative.
The current sampler test proves propagation and admission cleanup, but does not
assert the final runtime state or an exact post-observer call count. A future
runner-hardening revision may add a minimal terminal record only if it preserves
propagation and passes the same instrumentation-neutrality gate; until then,
cancellation is external run evidence and the absence of a completed sample
remains explicit.

Before, in-operation, and after snapshots cover every current TLS/Linux
count-only flow field plus admission, actor, SQLite database/journal/WAL/SHM,
process, cgroup, and event-loop fields. A snapshot is explicitly sequential,
not simultaneous: ordered adapter spans declare the owned fields, method, and
begin/end offsets for transport, admission, actor, SQLite, process, and loop
observations. The spans partition every value field exactly once and attribute
each missing field to exact reason codes. Missing observations are `null`,
never fabricated zeros. A runner without a stable internal hook emits an
all-null `in_operation_snapshot` with
`NO_STABLE_IN_OPERATION_HOOK`; it never constructs a synthetic fieldwise
"peak." The schema also rejects impossible driver states, zero socket buffers,
incoherent chunk/octet pairs, invalid staged/remaining ciphertext, and a
claimed complete parser unit without durable bytes.

Successful signed ingress returns the complete A1 grant through the
non-capability progress value: policy, epoch, admission sequence, command kind,
reservation, admitted/started/deadline loop-clock offsets, and queue wait. V5
does not admit inferred sole-caller attribution. Exact admission epochs cannot
regress within a sample and exact sequences must move strictly forward.

`correctness.json` is separate from performance. It commits the sample-stream,
RAW-ingress, actor-event, and projection roots and exact no-loss,
no-duplication, no-reordering, control-causality, projection-verification,
observation-completeness, and cleanup results. Observation completeness is
derived from exact sample coverage and admission attribution rather than
accepted as a caller assertion. A failed invariant requires a retained failure
code.

The preceding paragraph describes the intended finalized record, not a current
verification guarantee. The V5 provisional record fails closed at every
exposed correctness boundary: it must contain
`CORRECTNESS_FINALIZER_NOT_IMPLEMENTED`; `no_loss`, `no_duplication`,
`no_reordering`, `control_output_causal`, `projection_verified`, and
`cleanup_complete` must all be false; and only `observations_complete` may be
derived true from exact sample coverage. Direct construction, `from_mapping()`,
canonical JSON decoding, forged exact-type bundle `build()` and direct bundle
construction, correctness serialization/`passed` access, and fully rehashed
artifact replay reject a caller-authored PASS. A valid provisional record and
its exact four-member byte closure still round-trip.

This repair prevents an unfinalized V5 record from claiming PASS; it does not
derive the three roots or verify any of the six finalizer-dependent results.
Those values remain deliberately non-asserting commitments until a future
versioned evidence-derived finalizer is implemented and independently tested.

This profile intentionally has **no** summary or threshold artifact, class,
encoder, or export. Adding `summary.json`, `threshold_derivation.json`, or any
other fifth member makes replay fail. A future versioned analyzer may consume a
complete raw bundle and produce separately identified, regenerable
distributions. That later analysis must disclose instrumentation overhead,
retain links to the exact raw evidence-bundle IDs, and report at least:

- count, missing count, minimum, median, p95, p99, p99.9, and maximum;
- worst operation and sample IDs;
- occupancy time above each analysis candidate;
- recovery duration and oldest-data age;
- Ping/Pong, Close, ACK, shutdown, and event-loop latency;
- SQLite busy/transaction/commit duration;
- actor cost by retained-history size; and
- RSS, kernel, BIO, parser, actor, and storage high-water values.

Threshold derivation remains still later. It requires a new frozen calibration
schema, immutable calibration campaigns, independent confirmation campaigns,
and a separately signed A2-E threshold policy as described in section 8. No
current Python type or exploratory artifact is accepted as a shortcut to that
authority.

The fail-closed provisional invariant creates neither correctness nor threshold
authority. It only ensures that no current Raw V6 record can become a constructible
or replayable PASS before the future evidence-derived finalizer exists.

Quantile computation, interpolation, and treatment of censored/failed runs are
bound by the analysis-plan identity. Failed or incomplete runs remain visible
and cannot be removed from analysis without a preregistered exclusion reason.
Raw measurement bundles and future derived analyses are operational evidence;
they are not market observations or a replacement for actor terminal evidence.

### 6.5 Current V5 raw sampler, V2 workload mapping, and exact limits

The implemented runner accepts one canonical
`CapacityMeasurementIngressWorkloadSpecV49F`. Its canonical JSON fixes
`operation_kind=INGRESS`, workload family, stage, ordered base64 input chunks,
ordered expected logical Pong/Close frames, timeout, and workload-schema
version. The
runner reconstructs that specification from the trial and requires literal
canonical-JSON equality with the selected manifest workload before calling
`process_next_ingress_v49d()` exactly once. Returned ingress progress is then
checked against the declared ordered-RAW-batch hash and committed-octet count.
The runtime returns actor-ordered parser sources, durable dispatch-completion
IDs, actual serialized output chunks, per-logical-frame physical chunk counts,
and decoded logical opcode/payload frames in returned progress only after
dispatch completion. The actor's prepared-wire evidence records logical opcode,
payload hash/octet count, and serialized wire chunks earlier, before TLS/send.
The runner compares the returned logical frame sequence with the preregistered
oracle and persists logical and physical-output hashes, counts, grouping, exact
bytes, and exact chunk lengths. Replay reconstructs each physical frame,
requires one final masked Close/Pong control frame per logical group, unmasks
the payload, and requires equality with the persisted logical evidence.
It deliberately does not preregister serialized client wire bytes: WebSocket
client Pong/Close frames are masked with fresh entropy, so literal wire equality
would be the wrong oracle. Two different valid masks must retain the same
logical commitment while producing different physical bytes. This is an exact
mapping for the one ingress operation; it is not yet the non-ingress operation
union or proof that every section 7 workload family has been executed.

The V2 workload profile caps preregistered automatic-output frames at 32 and
validates control-frame payload/code/UTF-8 rules. The V5 raw sample separately
permits the causal worst-case observation bound of 32,768 minimum two-byte
ingress units in 65,536 pending RAW octets; this prevents the serializer
from failing merely because actual output exceeds the staged workload cap.
Such a run cannot pass an exact workload oracle above 32 in the current profile.
The raw sample permits at most 32 physical chunks per logical output and
1,048,576 physical chunks per ingress. Its exact physical-byte decoder cap is
4,292,608 octets: 32,768 possible automatic frames times the RFC 6455 maximum
131 wire octets for one masked control frame. This replaces the V4 profile's
deliberately loose 2 GiB metadata-only ceiling. These are source/artifact safety
bounds, not observed capacity, TLS-ciphertext limits, or candidates for
enforcement.
Parser-event, output-frame, source, completion, and chunk-group cardinalities
are bounded and cross-checked, but descendant lineage still requires replay of
the actor chain by the unfinished correctness finalizer.

The runtime, rather than the caller, supplies the projection database path.
The manifest storage identity binds the resolved path, device, and inode. The
local adapter verifies that identity at construction and rechecks the main
database device/inode when observing it. SQLite storage observations remain
sequential filesystem occupancy only: main-database, `-journal`, `-wal`, and
`-shm` lengths are read in order; an absent sidecar is represented as zero
sidecar bytes for that call and means only that no directory entry was
observed, while other `stat()` failures are unavailable. `sqlite_page_count`
and `sqlite_freelist_count` remain null with
`SQLITE_CONNECTION_PRAGMAS_NOT_SAMPLED`; no connection is re-entered and no
transaction, commit, durability, or logical-row conclusion is inferred.

The before and after observations execute these adapters sequentially. The
runner compares and persists initial, pre-operation, progress-returned, and
post-operation runtime boundaries containing actor tail/count and the complete
quiescent A1 snapshot. A competing
command between these boundaries invalidates the measurement as
`NON_TARGET_RUNTIME_ACTIVITY_DETECTED`; this detects observed contamination but
does not implement campaign-wide mutual exclusion. The
in-operation snapshot is all-null with `NO_STABLE_IN_OPERATION_HOOK`. No adapter
span is a simultaneous cross-layer state, and none authorizes backpressure,
parser quanta, SQLite policy changes, terminal actions, calibration, or live

threshold, calibration, confirmation, and A2-E enforcement authority do not

The current runner returns no partial progress when an exception occurs after
some parser units or automatic outputs have already completed. The V5 sample
retains the exception class, explicit returned-progress unavailability, and the

future attempt/terminal log and an evidence-correct operation-lineage

### 7.2 Runtime-artifact currentness amendment

A current static and dynamic audit explains the profile result. The admitted
closure contains 314 files: 7 primary runtime members, 3 bytecode-cache
members, 196 `cryptography` members, and 108 `websockets` members, totaling
57,260,695 bytes. One driver-currentness check hashes each file during current
policy capture, through its retained descriptor, and through the reopened
signed path: 942 complete hashes and 171,782,085 input bytes. One initial RAW
with one complete frame performs two checks around read, two around durable RAW
adoption, and two around the parser call. The no-automatic-output formula is:

```text
full authority checks H = 4 + 2P

P = owner parser calls
```

For one complete two-byte Pong frame this is six checks, 1,884 retained-member
verifications, 5,652 complete file hashes, and at least 1,030,692,510 bytes
passed through member-content hashing, excluding trust-store parsing,
`SSLContext` construction, import/mapping enumeration, and socket checks.

This is a V4.9B runtime-authority problem discovered and measured by A2-M; it
is independent from A3 actor-history reduction. The candidate order is:

1. As the portable immediate baseline, eliminate redundant content passes
   inside one check while preserving current path/descriptor identity and
   pre/post effect cadence. Mint an exact one-shot operation capability only
   after the check; reject clone, reuse, cancellation, cross-task, stale, and
   post-fork use.
2. Qualify [`fs-verity`](https://docs.kernel.org/filesystems/fsverity.html) for
   independently installed runtime files. Retain path, metadata, import,
   mapping, process, and owner checks; kernel-verified immutable content permits
   constant-time digest retrieval without treating metadata as content proof.
3. Qualify a separately built
   [`dm-verity`](https://docs.kernel.org/admin-guide/device-mapper/verity.html)
   image when the complete immutable runtime and trusted-root deployment chain
   are operationally feasible. Mutable SQLite/capture state must stay outside
   that image.

Metadata/mtime caches, startup-only hashes, periodic verification, retained-fd
only, package versions, or inotify/fanotify cleanliness are not equivalent to
the current fail-closed content boundary. Linux documents that an open file
description continues to reference its original object after a path is removed
or replaced ([`open(2)`](https://man7.org/linux/man-pages/man2/open.2.html)), and
notification queues can overflow
([`inotify(7)`](https://man7.org/linux/man-pages/man7/inotify.7.html)). Change
detectors may be early invalidation hints only; overflow or ambiguity forces
full verification or fail-closed handling. Parent-component and mount escape
also require an evaluated `openat2()` policy rather than relying only on
`O_NOFOLLOW` ([`openat2(2)`](https://man7.org/linux/man-pages/man2/openat2.2.html)).

No verifier change belongs in A2-E itself. A2-M must decompose and compare the
costs; V4.9B owns the exact verifier and operation-capability semantics; the
deployment gate owns verity provisioning and trusted roots; A2-E may consume
only a separately accepted authority. Until then, service thresholds cannot
hide or amortize this cost into a false parser guarantee.

## 8. Threshold-policy freeze

### 8.1 Frozen state model

The threshold policy uses three states:

```text
NORMAL
  -- any governed layer >= high --> PAUSED

PAUSED
  -- every required governed layer <= low --> NORMAL
  -- any hard byte/work/age/deadline limit --> BREACHED

BREACHED
  -- no recovery transition; converge one durable terminal outcome
```

Pressure entry is an OR across governed layers. Recovery is an AND across all
layers required by the policy. This prevents one recovered buffer from
restarting reads while another remains unsafe.

Each governed layer freezes:

- observation method and units;
- low, high, and hard values where byte/count occupancy applies;
- maximum oldest-item and pressure-episode age;
- sample/checkpoint cadence and unavailable-observation action;
- maximum indivisible input/output growth;
- pause, drain, resume, or breach action; and
- evidence field and terminal precedence.

For every byte-bounded layer, the analysis must demonstrate:

```text
0 <= low < high < hard

hard >= high
        + worst legal indivisible growth after the high observation
        + maximum automatic Pong/Close output attributable to that unit
        + durable pressure/terminal bookkeeping headroom
```

The low/high gap must exceed the measured in-flight burst that can arrive or be
generated after pausing. A threshold freeze based solely on a percentile,
average load, one run, or one host is rejected.

### 8.2 Signed threshold artifact

The freeze produces one canonical `v4_9f_a2_threshold_policy.json` containing:

- policy/schema/profile ID;
- source A2-M protocol and artifact roots;
- included and excluded run IDs with reasons;
- exact deployment, host, kernel, Python, OpenSSL, SQLite, websockets, and
  filesystem class;
- per-layer low/high/hard/age rules;
- parser frame/byte/work quantum;
- control-output, pressure-age, and terminal-convergence deadlines;
- SQLite busy/lock response and journal-mode decision;
- unavailable/failed measurement action;
- hysteresis and terminal precedence table;
- accepted one-unit overshoot rule;
- validation workload roots not used for calibration; and
- signer/reviewer identities and approval evidence.

Changing any threshold, observation method, workload class, binary/dependency,
SQLite mode, filesystem, or enforced layer creates a new policy identity and
requires revalidation. A2-E must refuse a deployment whose signed threshold
identity differs from its admitted runtime environment.

## 9. A2-E enforcement contract

### 9.1 Layer-specific action

- When parser, durable RAW, actor, or storage pressure reaches high, stop new
  socket reads and work on the already-durable prefix.
- When kernel receive occupancy is high but all downstream layers have signed
  headroom, drain the kernel. If downstream is also high, do not pretend that a
  read pause solved the condition; advance the pressure-age/hard-breach test.
- When kernel send or outgoing TLS pressure is high, do not admit a later output
  ahead of the current actor-owned wire obligation. Converge the current
  obligation under its unchanged physical deadline or record terminal
  uncertainty.
- Before every memory-BIO write, prove sufficient signed hard-limit headroom for
  the entire indivisible write or fail before mutation. Sample pending bytes
  before and after.
- An unavailable required observation is fail-closed according to the signed
  policy. It is never interpreted as zero occupancy.

### 9.2 Hybrid service quantum

One parser turn is bounded by the first reached limit among:

- completed durable frame/error units;
- consumed source octets;
- signed work units derived from measured parser/application/actor operations;
  and
- an observed elapsed/CPU watchdog checked between indivisible units.

At least one already-started legal unit must reach a stable outcome to avoid
deadlock. Any overshoot is limited to one signed maximum indivisible unit and is
reported. Elapsed time is not the sole correctness limit because synchronous
work cannot be preempted.

A stable quantum boundary is after:

```text
complete next wire-ordered unit consumed
-> parser transition durably appended
-> completed application message durably committed, if any
-> generated automatic output durably prepared and physically converged,
   or its exact terminal uncertainty durably converged
-> parser cursor, retained tail, source slices, and fragment state retained
```

A2-E may not yield between parser mutation and durable parser evidence, between
automatic-output creation and its actor-owned completion, or inside an
indivisible SQLite transaction whose outcome is not known.

### 9.3 Causal correction: RAW order survives cooperative quanta

A cooperative parser turn is a scheduling unit, not a new observation or RAW
admission. The residual complete frames remain owned by the original durable
RAW and the original ingress admission.

Each continuation therefore retains two distinct identities:

```text
causal_ingress_identity:
    original A1 admission epoch/sequence
    original RAW ingress sequence and commit ID
    original projection receipt sequence/hash
    original stream offsets and source slices

service_turn_identity:
    the later bounded execution turn used to resume work
```

The service-turn identity must never replace the causal-ingress identity in a
parser/application event. A continuation may be scheduled later, but it cannot
make the retained bytes appear newly received.

Before any subsequent socket read or `RAW_INGRESS_COMMITTED` append:

```text
no older complete durable parser unit remains
and no automatic output obligation from that prefix remains unresolved
```

Any call reaching the ingress boundary while residual complete work exists is
converted into a parse-only continuation before the owner read seam. It cannot
read RAW N+1 and later return to complete RAW N. The driver guard remains a
defense, not the scheduler.

Other actor commands may interleave only at the stable boundary above and only
according to a versioned precedence table. Their actor-event positions remain
the actual durable order. An implementation which releases A1, re-admits the
residual bytes at the FIFO tail, and loses the original causal admission
identity is rejected. An implementation which retains the lock and merely
calls `sleep(0)` may improve general loop responsiveness but does not provide
transport-command service; it must not claim otherwise.

The A2-E design must choose and test one explicit continuation mechanism:

1. a retained logical-ingress continuation capability with immutable original
   causal identity and separately recorded service turns; or
2. a new versioned A1 lifecycle supporting `YIELDED_WITH_CONTINUATION` without
   allowing a later RAW read to overtake it.

This choice is part of A2-E implementation review. Neither mechanism may be
backported by silently changing accepted A1 grant semantics.

### 9.4 Automatic control output

RFC 6455 permits control frames within fragmentation but preserves wire order.
A2-E therefore never scans unread bytes for a Ping or Close and never parses a
later control frame ahead of an earlier frame.

Once the next unit causally creates Pong or Close output, that unit is not
complete until the current actor/TLS/kernel contract records full acceptance or
the exact terminal uncertainty. A quantum boundary cannot strand generated
control bytes in an unowned local queue.

The threshold policy freezes a measured project control-output objective. It
must be described as a RiskYieldMM service objective, not as a numeric RFC
deadline.

### 9.5 Durable pressure and terminal evidence

Local samples remain measurement artifacts. Actor events are appended only on
state transitions to avoid turning sampling rate into unbounded durable
history. The candidate event set is:

```text
CAPACITY_PRESSURE_ENTERED
CAPACITY_PRESSURE_RECOVERED
CAPACITY_BREACH
```

Each event binds at least:

- capacity policy, episode, session, epoch, and original causal admission;
- triggering layer and threshold identifier;
- observed occupancy, oldest age, high/hard value, and observation method;
- first-high and transition BOOTTIME/wall evidence;
- RAW commit/parser cursor/actor-tail identity;
- current automatic-output and terminal obligations; and
- predecessor event/hash and final-writer authority.

`CAPACITY_PRESSURE_ENTERED` occurs once per episode. Recovery occurs once only
after all required layers are at or below low. A hard byte/work limit,
freshness/episode-age limit, control-output deadline risk, or required
observation failure converges `CAPACITY_BREACH` under the frozen policy.

The breach event and actor-owned `BACKPRESSURE` terminal should be committed in
one consecutive atomic actor/projection batch where the storage contract can
do so. If the append or transaction itself fails or is uncertain, the system
must classify storage failure/fault-latched uncertainty. It must not claim that
a BACKPRESSURE terminal was durably recorded.

### 9.6 Terminal precedence

The A2-E adversarial oracle freezes at least these rules:

1. an existing durable terminal remains final;
2. an already-started local shutdown or automatic Close obligation converges
   before a newly observed overload terminal;
3. the next complete durable wire unit is processed in order; an unparsed Close
   in kernel/TLS buffers is not claimed as observed;
4. a due actor-governed deadline follows its admitted command and durable
   precedence rather than an out-of-band timer callback;
5. a capacity breach observed at a stable boundary may become final only if no
   earlier causal obligation owns the final writer; and
6. storage failure while recording pressure/breach is storage uncertainty, not
   successful BACKPRESSURE.

Internal termination reason and wire Close code are separate fields. The
baseline is durable fencing followed by a bounded Close attempt only when the
policy proves output headroom; otherwise use the existing fail-stop/abort
semantics. Code 1013 remains a provider-qualified challenger, not a default.

### 9.7 SQLite enforcement choice

The present synchronous 5000 ms busy timeout is retained during A2-M so the
current failure mode is measured faithfully. Before A2-E acceptance, the
threshold freeze must choose one storage protocol:

- a fail-fast or measured short synchronous busy limit compatible with the
  signed loop/control objective, with explicit storage-failure convergence;
- a separately designed serialized writer thread/process which exclusively
  owns its SQLite connection and preserves exact request/result FIFO,
  capability identity, cancellation, crash recovery, and effect certainty; or
- a certified WAL/checkpoint configuration which still accepts the one-writer
  limitation and passes filesystem, reader-starvation, crash, and latency
  campaigns.

Wrapping the current thread-bound connection in an executor is not an accepted
protocol. `asyncio.wait_for()` around the existing synchronous call is not a
bounded-storage implementation.

## 10. A2 acceptance contract

### 10.1 A2-M completion

A2-M is complete only when:

- every required layer has either a tested observation or an explicit
  `UNAVAILABLE` result with fail-closed threshold implications;
- deterministic instrumentation-on/off durable prefixes and physical outcomes
  are identical;
- artifacts are complete, schema-valid, hash-closed, and reproducible from
  their workload/deployment manifests;
- sampling failures and failed workloads remain in the raw sample stream and
  any future derived analysis;
- all frozen workload families and negative controls have run; and
- measurement overhead and missing-sample rates are reported by workload and
  checkpoint.

A2-M completion does not authorize enforcement.

The current implementation is **not** A2-M completion. Raw V6 preserves the V5
timing/outcome/admission/causal-output evidence and supplies the locally
accepted manifest-authority boundary. Accepted Raw V7 adds durable pre-effect
attempts, exactly-one terminals, exact failed-prefix reconstruction,
cancellation/interruption propagation, and startup orphan recovery while
keeping unavailable partial-effect progress distinct from a legitimate empty
prefix. Literal deterministic-prefix and physical alpha-equivalence comparator
types exist, but the physical normalizer and matched neutrality campaigns do
not.

Every Raw V7 correctness path remains deliberately provisional and non-passing
because no independent finalizer or post-run provenance attestation exists. Its
current acceptance evidence is **242 direct cases** plus the exact frozen
**39-file / 558-case adjacent matrix**. The **228-test Raw V6** result and
historical **2,441 passed, 32 skipped** repository run remain dated predecessor
evidence, not current full-suite claims.

The accepted Raw V6 and Raw V7 sub-gates close manifest authority and bounded
failed-prefix/cancellation lifecycle evidence, respectively. The remaining
sequential A2-M gaps are:

1. stable bounded in-operation markers, the non-ingress operation union, and
   every remaining target-layer field or explicit fail-closed unavailability;
2. a reviewed physical event-field normalizer plus fixture-level deterministic
   OFF/OFF, ON/ON, and OFF/ON oracles;
3. an independently evidence-derived finalizer for roots and correctness
   results without weakening the provisional fail-closed invariant;
4. campaign isolation distinct from retrospective contamination detection;
5. atomic durable publication, collision/restart behavior, and immutable
   campaign artifacts; and
6. complete matched neutrality/overhead and frozen workload campaigns through
   those accepted surfaces, followed by review gates before calibration,
   confirmation, thresholds, or enforcement.

### 10.2 Threshold-freeze completion

The threshold policy is frozen only when:

- calibration artifacts are immutable and independently reviewed;
- low/high/hard inequalities and hard-limit headroom are demonstrated per
  layer;
- no value depends only on an average, one percentile, one run, or one host;
- exact software/host/filesystem applicability is declared;
- the SQLite and wire-Close choices are explicit;
- fresh validation workloads and seeds were not used to select values; and
- the canonical policy is signed and propagated through deployment capability
  and runtime admission identity.

## 11. Exact A2, A3, and B boundaries

### V4.9F-A2 owns

- measurement artifacts and layer observation semantics;
- signed per-layer watermarks, ages, hard limits, and unavailable actions;
- transient read pause versus terminal freshness/capacity breach;
- cooperative parser frame/byte/work turns;
- original durable RAW identity across continuations;
- automatic Pong/Close completion before yield;
- actor-owned capacity transition and BACKPRESSURE terminal evidence;
- SQLite contention measurement and the bounded A2 storage response; and
- single-session adversarial pressure and causal replay.

### V4.9F-A3 owns

- incremental actor-state reduction instead of cumulative full-prefix rebuild;
- bounded live actor history/cache and checkpoint/reload semantics;
- incremental validation with differential full-replay verification;
- history-independent append/reduce complexity claims;
- 10k/100k-event correctness, memory, latency, and crash-prefix evidence; and
- any schema/checkpoint changes required to make those bounds durable.

A2 may measure and expose actor/history growth. It must not solve A3 by hiding
old events, skipping validation, weakening replay, or declaring a count/byte
quantum to be a wall-time bound. A2-E can be implementation-complete while A3
remains closed, but the public factory and end-to-end bounded-service claim
remain closed. If A2-M shows actor/history cost dominates a signed service
objective, A3 becomes a blocking dependency for A2 operational promotion.

### V4.9F-B owns

- supervisor-owned queues across independent sessions/scopes;
- measured work charging derived from accepted A2/A3 artifacts;
- cross-session admission, capacity partitioning, and fairness;
- DRR or another scheduler challenger;
- 100-scope burst/fairness/capacity campaigns; and
- supervisor crash/restart and session-isolation behavior.

B may not reorder frames, RAW batches, actor commands, or automatic output
inside one session. Starting DRR before A2/A3 would distribute unbounded and
unmeasured work and is rejected.

## 13. Public factory and promotion boundary

The public live factory remains closed throughout A2-M, threshold analysis,
and initial A2-E implementation. The expected behavior remains:

```text
structurally valid live-factory inputs
-> transferred socket closed
-> fail-closed denial
-> no LinuxPhysicalTransportRuntimeBundleV4 returned
```

Opening it requires post-V4.9F integrated promotion and operational
qualification, including A3/B where required, provider and certificate
conformance, privileged host/clock validation, crash/storage campaigns,
measured immutable deployment, longer soak/capacity evidence, and the other
Stage 1 gates. A passing A2 test must not change exports, construction tokens,
or live-factory denial.
