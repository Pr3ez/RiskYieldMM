## 2. Architecture decision

Three viable execution boundaries were compared:

1. import and execute the generic typed runtime inside the verifier;
2. trust the C2 attainer checker or certificate as proof of P1; or
3. implement a closed verifier-owned static subset and compare it with the
   separately pinned generic runtime only in differential tests.

The third design remains the narrowest independent boundary. Dynamic execution
would expand the trusted interpreter surface and violate the static source
isolation contract. Trusting C2 would collapse the independent verifier and
producer-side evidence channels. V3 therefore:

- statically validates compact canonical JSON, record and tagged-union shapes,
  scalar constraints, exact authority pointers, and reference closure;
- reconstructs the exact five application schedules, invocation ordinals,
  cardinalities, root/sequence bindings, and resolver bindings;
- executes the closed descriptor, aggregate-field-context, A1 FIFO,
  root-membership, and selector-lifecycle semantics required by case 435;
- uses a safe object-identity target-index cache that changes no semantic
  result and is exercised by the independent generic-runtime differential;
- emits complete individual context objects only after the packed input has
  passed all semantic and file-closure checks; and
- retains the generic runtime as an out-of-process oracle, never as verifier
  implementation authority.

No external literature search was needed for this packet. Its truth conditions
are local byte identities, repository-defined opcodes, accepted authority
contracts, and deterministic resource equations; external sources cannot
establish those facts.

The V3 acceptance suite rejects, after full resealing where applicable:

- use of the old exact-delta boundary or predecessor case-435 plan;
- producer-authored certificate claims and the inherited flat encoding;
- changed program schedule, invocation ordinal, authority reference, or
  inventory pointer;
- missing, duplicate, inline-witness-duplicating, noncanonical, extra-file, or
  otherwise non-closed packs;
- descriptor-policy false, aggregate field-context false, A1 FIFO false,
  root-membership false, selector-lifecycle false, and one-byte-short P3;
- codec oversize and malformed/noncanonical record representations; and
- any attempt to dynamically import the producer, C2 checker, generic runtime,
  or a validation implementation into the verifier.

the verifier. Positive representatives of all five application families match

failure coordinates, P1-true/P3-false remains distinct, A1 FIFO true/false
